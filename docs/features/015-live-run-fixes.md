# 015 — Первый живой прогон в клиенте Telegram

Статус: **done** (кроме пунктов в «Что осталось»). Сделано 2026-09-06, сразу после `014`.

Приложение впервые открыли в настоящем клиенте на телефоне — то, чего не хватало `008`–`013`, каждый из которых заканчивался строкой «в настоящем клиенте не проверено». За вечер вылезло четыре вещи, и ни одну не поймали бы ни тесты, ни вычитка диффа: три про поведение клиента, одна про то, как выглядит 22-пиксельная картинка на реальном экране.

## 1. Вход не работал: `bad-signature` на живых данных

Симптом: каталог открывается, а профиль всё время показывает «Профиль виден из Telegram». В логе — `Вход отклонён: bad-signature`.

Причин оказалось **две, одна за другой**, и обе выглядели одинаково.

**Первая — токен.** В `.env` он лежал с двумя лишними символами на конце. Опечатка и подделка неотличимы по симптому: `initData` приходит настоящий, подпись не сходится, в логе одно и то же слово. А лечатся они по-разному.

**Вторая — состав строки подписи.** Документация Telegram («Validating data received via the Mini App») велит исключать из строки поля `hash` **и** `signature` — второе появилось в Bot API 7.10 для сторонней проверки по Ed25519. Так и было сделано. Настоящий клиент считает иначе: `signature` у него в подписываемой строке **остаётся**.

Как нашли: временный перебор — те же данные с телефона прогнали через шесть вариантов строки (исключать `hash` / `hash`+`signature`; декодировать через `URLSearchParams` / `decodeURIComponent` / не декодировать вовсе) и сравнили с присланным `hash`. Сошёлся ровно один — «убрать только `hash`». После этого перебор из кода убран: он был нужен один раз.

Теперь принимаются **оба** варианта, и в коде записано, чем за это платим: приняв документальный вариант, мы выводим само поле `signature` из-под подписи — к чужому валидному `initData` можно дописать `&signature=что угодно`, и проверка пройдёт. Это ничего не даёт: `signature` мы не читаем вовсе, а чтобы дописать, нужен уже украденный `initData`, который и без дописки годится, пока не истекло окно свежести. Отказаться от второго варианта — значит поверить, что все клиенты считают `hash` как этот; проверить это можно только на устройствах, а цена ошибки — покупатель, который не может войти.

**Чтобы следующий такой вечер не повторился**, добавлены две вещи:

- **`getMe` при старте API.** В логе теперь либо `Бот подключён: @имя`, либо `TELEGRAM_BOT_TOKEN отвергнут Telegram (401)`. Ничего не роняет и не выключает: без сети — просто предупреждение, сама проверка подписи сети не требует. Таймаут 5 секунд, потому что в сети, которая дропает пакеты вместо отказа, `fetch` висел бы дольше, чем проба готовности ждёт контейнер.
- **Имена полей в логе отказа**, без значений. Именно они показали бы `signature` сразу. Имена приходят из тела запроса, поэтому чистятся: перевод строки внутри имени дорисовал бы в лог поддельную строку, а тысяча выдуманных полей — килобайты на каждый запрос.

## 2. Шапка Telegram зависела от способа запуска

Из кнопки меню бота клиент рисовал сверху свою полосу с именем бота и «Назад», а из чата приложение открывалось без неё. Один и тот же магазин выглядел по-разному в зависимости от того, откуда в него зашли.

Приложение теперь само просит полный экран (`requestFullscreen`, Bot API 8.0) — полосы нет нигде, остаются только плавающие кнопки клиента поверх содержимого. У клиента младше 8.0 метода нет, и всё остаётся как было; проверка версии обязательна — `?.` спасёт от падения, но не от молчаливого «ничего не произошло».

Просьба уходит **один раз за жизнь приложения**: `start()` переехал в отдельный эффект. В эффекте входа он перезапускался бы при смене токена (сервер отверг — вошли заново), и покупателя, который сам вышел из полного экрана, затаскивало бы обратно.

**Отступы под вырез и кнопки клиента.** В полном экране приложение рисует под часами и под «Закрыть», поэтому клиент отдаёт два запаса отдельно: `safeAreaInset` — устройство (вырез, скруглённые углы), `contentSafeAreaInset` — его собственные кнопки. Складываются и уходят в токены кита `--safe-top` / `--safe-bottom`; их берут шапка (`AppBar`) и главная, у которой шапки нет.

Если клиент отступов не даёт (младше 8.0, обычный браузер, тесты), токены не трогаются вовсе: в ките они посчитаны из `env(safe-area-inset-*)`, и записать туда ноль значило бы стереть рабочее значение ради пустого. Чтобы этот запасной путь действительно работал, в `index.html` добавлен `viewport-fit=cover` — без него `env(safe-area-inset-*)` всегда 0.

## 3. Нативная кнопка «назад» убрана совсем

Внутри клиента шапка отдавала «назад» ему (`BackButton`) и прятала свою — ради одной кнопки вместо двух (`008`). В живом клиенте это оказалось хуже: кнопка ведёт по истории, а история растёт от переходов вглубь, и с экранов, открытых вкладкой нижнего бара, «назад» означало «выйти из приложения». Кнопка обещала одно, делала другое.

Теперь клиент показывает только «Закрыть», а навигация целиком наша — одна модель поведения и в Telegram, и в браузере. Вместе с `attachNativeBack` ушёл контекст «виден ли слой» из `ScreenLayer`: он существовал ровно затем, чтобы кнопка карточки не залипала в каталоге, то есть охранял место **вне** своего слоя. Своя кнопка живёт внутри слоя, а скрытый через `visibility` слой выпадает из дерева доступности сам.

**Стрелки «назад» больше нет на экранах-вкладках** — каталог, корзина, профиль (у главной шапки нет вовсе). Вкладки не кладут запись в историю намеренно (`012`): переход между ними — один уровень, а не путь вглубь. Там, куда заходят вглубь — карточка, оформление, заказы, — стрелка осталась и возвращает на ту вкладку, с которой ушли.

Тестов на это раньше не было ни в ту, ни в другую сторону: правка про кнопку прошла бы молча. Теперь у каждого экрана-вкладки есть проверка, что стрелки нет.

## 4. Маскот из шапки убран

Голова, выглядывающая из-за названия раздела (`013`), на телефоне читалась пятном: белая собака на кремовом фоне, наполовину закрытая словом, повёрнутая на 45°. Сначала попробовали починить — 30px вместо 22 (порог дизайн-системы 28, старое значение жило «на границе») и наклон 28° вместо 45, чтобы силуэт с ушами читался первым. На экране телефона это всё равно не заработало, и владелец решил снять до лучших времён: заголовки остались текстом.

Компоновка `Logo variant="head"` и `AppBar titleBleed` в ките остались — они рабочие и понадобятся, когда у маскота появится **цветной вектор**. Нынешняя голова вырезана из растра, который сам вырезан из JPEG-скриншота 361×442; на 22–30px это и есть предел.

Это первый случай, когда решение из `docs/features` отменяется по результату живого прогона. `013` остаётся в истории как есть, со статусом «откачено в `015`».

## Проверено

Живьём, в клиенте Telegram на телефоне, через публичный адрес из `014`:

- Вход проходит: профиль показывает покупателя, в логе API — `Бот подключён: @MikkiWithLove_bot` вместо `bad-signature`.
- Полный экран при обоих способах запуска: из кнопки меню бота и из чата. Полосы с именем бота нет, сверху только «Закрыть» и «…».
- Заголовок раздела не заезжает под часы и под кнопки клиента.
- Стрелки «назад» нет в каталоге, корзине и профиле; есть в карточке, оформлении и заказах.

Локально: `lint` / `typecheck` / `test` (418) / `build` — чисто. Проверка подписи закрыта тестами на **обе** формы `initData` — с `signature` внутри строки подписи и вне её, — чтобы следующая правка «по документации» уронила тесты, а не вход покупателя.

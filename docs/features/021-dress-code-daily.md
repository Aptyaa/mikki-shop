# 021 — Дресс-код дня

Статус: **план** — код не написан. Ступень G4 трека `docs/roadmap-game.md`.
Требует `018` (примерочная), `019` (правила оценки) и `020` (промокоды).

## Что это

Собственно игра. Раз в сутки — событие и спрятанный образ из трёх слотов.
Четыре попытки; после каждой по каждому слоту приходит подсказка:

- 🟢 **эта вещь** — попал точно;
- 🟡 **та категория, не та вещь** — слот угадан, предмет нет;
- ⬜ **мимо**.

Результат — сетка квадратиков, которой делятся в чат Telegram. Пять сыгранных
дней подряд дают промокод.

## Почему это последняя ступень, а не первая

Угадайка — самая рискованная механика из всех: она единственная умеет
раздражать. Если сцена не отполирована, гардероб мал, а разбор образа не
работает, четыре неудачные попытки подряд закрывают приложение навсегда.

Зато это единственная механика, которая делится в чат, а весь рост магазина —
из трафика. Поэтому она в плане есть, но идёт после всего остального.

**И у неё есть право на неудачу.** Если после запуска люди не возвращаются на
второй и третий день — ступень откатывается до `019`, а примерочная остаётся.
Это нормальный исход, а не провал: три предыдущие ступени полезны и без неё.

## Раунд

- **Один раунд в сутки на всех.** Не персональный: общий раунд — это то, что
  делает сетку квадратиков осмысленной («у меня с третьей попытки, а у тебя?»).
- **Событие и загаданный образ выбираются детерминированно от даты.** Псевдослучайно
  по сиду `YYYY-MM-DD`, из событий `019` и гардероба `018`. Никто не пишет
  контент руками — при гардеробе в 12 вещей комбинаций хватает надолго.
- **Три слота из пяти.** Какие именно — часть загадки дня.
- **Сутки считаются по московскому времени**, а не по времени устройства: раунд
  общий, и «день» у всех обязан быть одним и тем же.

## Античит — не опция

Спрятанный образ и разбор попыток живут **только на сервере**. Клиент отправляет
догадку и получает три цветных отметки — и ничего больше. Если ответ приедет на
клиент «чтобы не гонять запросы», его увидят в DevTools в первый же день, и игра
кончится.

Отсюда:

- `GET /game/round/today` — событие дня, число оставшихся попыток, история
  прошлых догадок. **Без ответа.**
- `POST /game/round/guess` — догадка, ответ: отметки по слотам и, если попытки
  кончились или образ угадан, сам ответ с разбором.
- Попытки считает сервер по `userId`. Гость играть может, но его прогресс живёт
  в `localStorage` и в серию не идёт — правило 6 трека.

## Данные

```prisma
/// Раунд суток. Строка на день, а не вычисление на лету: ответ должен
/// остаться прежним, даже если гардероб поменяли посреди дня.
model GameRound {
  id        String   @id @default(uuid())
  /// Дата раунда по МСК, «2026-09-08». Строкой: сравнивается на равенство,
  /// арифметики по ней нет.
  day       String   @unique
  eventKey  String
  /// Слаги загаданных вещей. Наружу не отдаётся до конца раунда.
  answer    String[]
  createdAt DateTime @default(now())

  plays     GamePlay[]
}

/// Участие человека в раунде: попытки и итог.
model GamePlay {
  id       String   @id @default(uuid())
  roundId  String
  round    GameRound @relation(fields: [roundId], references: [id], onDelete: Cascade)
  userId   String
  user     User      @relation(fields: [userId], references: [id], onDelete: Cascade)

  /// Догадки по порядку, каждая — тройка слагов.
  guesses  Json      @default("[]")
  solved   Boolean   @default(false)
  finishedAt DateTime?
  createdAt  DateTime @default(now())

  @@unique([roundId, userId])
  @@index([userId])
}
```

`@@unique([roundId, userId])` — то, что физически не даёт переиграть день.

Серия считается запросом по `GamePlay` (дни подряд, где есть участие), а не
хранится счётчиком: счётчик разъезжается с реальностью при первой же ошибке в
логике, а запрос — нет.

## Награда

По правилам `020`: **пять сыгранных дней подряд — фиксированный промокод**.

Именно сыгранных, а не выигранных. Награда за удачу не даёт возвратов, награда
за привычку — даёт. И она не наказывает того, кто честно играл и не угадал.

Выдача идёт через `020`: создаётся `PromoGrant` по правилу `game-streak-5`, один
активный на человека. Повторно серия засчитывается, только когда предыдущий код
использован или истёк.

## Поделиться

Текст вида:

```
Дресс-код дня · Дождь и +8
🟢🟡⬜
🟢🟢⬜
🟢🟢🟢
Три попытки. Микки Шоп
```

Ответ в текст не попадает — иначе первый же поделившийся портит день всем
остальным. Уходит через `shareURL` адаптера Telegram (дополняется в `018`).

## Что здесь легко сделать неправильно

- **Ответ на клиенте.** Названо выше, повторено намеренно: это единственная
  ошибка, которая убивает механику целиком.
- **Часовой пояс устройства.** Переведённые часы на телефоне не должны давать
  второй раунд за сутки.
- **Смена гардероба посреди дня.** Ответ уже выбран и лежит в `GameRound` —
  поэтому его туда и записывают, а не вычисляют на каждый запрос.
- **Слишком большой гардероб.** Угадать одну вещь из тридцати — не игра, а
  перебор. В раунде участвует ограниченный набор кандидатов по каждому слоту, и
  игрок его видит.
- **Тон при проигрыше.** Четыре промаха подряд — момент, когда человек уходит.
  Экран после неудачи показывает правильный образ, объясняет его по правилам
  `019` и предлагает примерить — а не «повезёт завтра».

## Готово, когда

- Раунд один на сутки, переиграть нельзя, ответ не видно в сетевых запросах.
- Серия считается верно, включая пропущенный день посередине.
- Промокод выдаётся один раз за серию и не дублируется.
- Проверено в настоящем клиенте Telegram, включая шаринг в чат.

## Метрика, ради которой всё

Возвраты на второй и третий день. Если их нет — см. «право на неудачу» выше.

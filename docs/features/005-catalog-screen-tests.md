# 005 — Тесты экрана каталога

Статус: **done** (проверено локально 2026-09-03)

Продолжение [[004-test-suite]]: там появился раннер и тесты на логику под экраном — контроллер, сервис, клиент каталога, склонение. Сам `CatalogScreen` остался непокрытым, а в нём живёт вся логика, которую видит пользователь: накопление страниц, счётчики, дебаунс поиска, доступность размеров.

## Что сделано

**jsdom и Testing Library** в `apps/telegram-app`: `jsdom`, `@testing-library/react`, `@testing-library/dom`, `@testing-library/jest-dom`.

**Окружение переключается docblock'ом**, а не конфигом: в шапке файла стоит `// @vitest-environment jsdom`, корневой `environment` остаётся `node`. Разводить монорепо на проекты Vitest ради одного файла незачем, а `environmentMatchGlobs` в Vitest 3 объявлен устаревшим. По той же причине матчеры `@testing-library/jest-dom/vitest` импортируются прямо в файле, а не глобальным setup-файлом.

**Подменяется только сеть.** `vi.mock` на `../api/catalog`, дальше экран рендерится целиком, вместе с дизайн-системой: `ProductCard`, `Sheet`, `SizeSelector` — настоящие. Тест ходит по экрану так же, как пользователь: ищет кнопку по доступному имени, полосу — по тексту.

**`fireEvent`, а не `user-event`, и никаких фейковых таймеров.** В экране есть дебаунс на 300 мс, а связка «фейковые таймеры + `waitFor` + react-query» — известный источник плавающих падений. Дебаунс проверяется по факту: сразу после ввода нового запроса нет, а нужный доезжает. `@testing-library/user-event` был поставлен и снят — без него тесты короче и устойчивее.

**12 тестов:**

- выдача: первая страница, оба счётчика (`total` в шапке против `matched` в полосе), пустая выдача рисует объяснение, а не пустую сетку;
- «Показать ещё»: догружает страницу *к* показанным, обещает остаток, когда он меньше страницы, и исчезает, когда загружено всё;
- сбой сети: сообщение и повтор по кнопке;
- фильтры: смена категории уходит в запрос, сброс с пустой выдачи возвращает `all`, выбранный размер не гасится, даже когда его нет в выборке;
- поиск: дебаунс, очистка крестиком, сворачивание поля снимает фильтр.

**Проект поднят с Node 20 на Node 22.** jsdom 30 и `@testing-library/jest-dom` 7 требуют Node ≥22, а CI был закреплён на 20 — тесты экрана были зелёными локально и не запускались бы в CI вовсе. Поймано на ревью и воспроизведено: под Node 20.19.4 файл падает с `TypeError: webidl.util.markAsUncloneable is not a function` (это undici внутри jsdom), прогон показывает `4 passed (5)` — двенадцать новых тестов просто не выполняются.

Сначала пробовал минимальный путь — понизить jsdom до 29, чей `engines` обещает `^20.19.0`. Обещание оказалось неверным: undici 7.29 внутри неё зовёт тот же `markAsUncloneable`, и под Node 20 всё падает так же. Поэтому поднят рантайм, а не понижены зависимости — тем более что Node 20 ушёл в EOL в апреле 2026.

Тронуто: `node-version` в CI, `engines.node` в корневом манифесте, `node:20-alpine` → `node:22-alpine` в обоих Dockerfile, `@types/node` в API, строка требований в README.

## Проверено вживую

Восемь мутаций экрана, после каждой — откат:

| Что сломано | Упало тестов |
| --- | --- |
| `getNextPageParam` всегда возвращает `undefined` | 2 |
| кнопка обещает целую страницу вместо остатка | 1 |
| выбранный размер тоже гасится | 1 |
| сворачивание поиска не чистит запрос | 1 |
| страницы подменяют друг друга вместо накопления | 1 |
| подзаголовок считает выдачу, а не каталог | 1 |
| убран дебаунс — запрос не доезжает | 3 |
| пустая выдача рисуется как сетка | 2 |

**Мутация «выбранный размер тоже гасится» сначала не поймалась — тест был пустым.** Он проверял размеры сразу после клика, а экран на время загрузки держит предыдущий ответ (`placeholderData: keepPreviousData`), так что проверка читала старые доступные размеры и проходила при любой логике. Починка: новый ответ сужает выдачу до трёх товаров, тест ждёт полосу «Показано 3 из 3» и только потом смотрит на кнопки. После этого мутация ловится. Ровно то, ради чего мутации и гоняются: зелёный тест и работающий тест — не одно и то же.

Остальное: чистая установка (`rm -rf node_modules **/dist` → `pnpm install --frozen-lockfile`), затем `lint` / `typecheck` / `test` / `build` — чисто, 61 тест; прогон с корневым `.env` и без него; в `apps/api/dist` и `apps/telegram-app/dist` нет `*.test.*`.

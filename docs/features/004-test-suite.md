# 004 — Тесты: Vitest и джоба в CI

Статус: **done** (проверено локально 2026-09-03)

До этого в репозитории не было ни одного теста и ни одного тестового раннера: CI гонял `lint`, `typecheck`, `build`. Клампы пагинации из [[003-catalog-pagination]] и фасет размеров были проверены руками через `curl` — и на этом их проверка заканчивалась.

## Что сделано

**Раннер — Vitest, один на всё монорепо.**
- Корневой `vitest.config.mts`, `include: apps/*/src/**/*.test.{ts,tsx}` и то же для `packages`. Тесты лежат рядом с кодом, а не в отдельном дереве `test/`: при переезде модуля тест едет вместе с ним.
- `environment: "node"` по умолчанию: всё, что проверяется здесь, — чистая логика, ни БД, ни DOM. Файлу, которому нужен DOM, окружение переключается docblock'ом в его же шапке — см. [[005-catalog-screen-tests]].
- Расширение `.mts`, а не `.ts`: у корневого `package.json` нет `"type": "module"`, и с `.ts` Vite грузит config через устаревший CJS-API и печатает предупреждение на каждый прогон.
- Скрипты: `pnpm run test` (разовый прогон) и `pnpm run test:watch`.
- `env: { VITE_API_URL: "" }` в конфиге. Корень Vite здесь — корень монорепо, поэтому корневой `.env` подхватывается в `import.meta.env`, и `VITE_API_URL=http://127.0.0.1:3001` из `.env.example` подставлял боевой хост в `BASE_URL` клиента каталога. Четыре теста падали у всех, кто завёл `.env` по README, и были зелёными только в CI, где `.env` нет. Ровно тот класс багов, про который написано в `CLAUDE.md`, — найден на ревью и воспроизведён через `cp .env.example .env`.
- Взят **Vitest 3, не 4**. У четвёртого в пирах `vite ^6 || ^7 || ^8`, а `apps/telegram-app` собирается на Vite 5. Апгрейд Vite — отдельная задача со своим риском для сборки, тянуть его прицепом к тестам не за чем.

**Джоба в CI.**
`pnpm run test` встал в `check` между `typecheck` и `build` — тесты дают более раннюю обратную связь, чем сборка.

**`apps/api/tsconfig.build.json`.**
Тесты лежат в `src`, а у API `rootDir: "src"` и `outDir: "dist"` — то есть `nest build` компилировал их в продовый образ вместе с `import { vi } from "vitest"`. Nest CLI по умолчанию берёт именно `tsconfig.build.json`, если файл есть; в нём `exclude: ["src/**/*.test.ts"]`. `typecheck` по-прежнему идёт по `tsconfig.json` и тесты проверяет.

**49 тестов на четыре модуля.**

- `catalog.controller.test.ts` — разбор query. Ровно те клампы, что в 003 проверялись руками: `limit` 8 по умолчанию и 48 максимум, мусор и отрицательные значения к дефолту, `offset` к нулю, размер и сортировка сверяются с известным набором, поиск подрезается по краям и до 100 символов. Категория намеренно проходит как есть, включая неизвестный ключ.
- `catalog.service.test.ts` — сборка запроса к Prisma на подставном клиенте, без БД. Тай-брейкер по `id` в каждой сортировке; фасет размеров считается по `scope`, а не по `where` (иначе в шите остаётся одна кнопка — та, что сама себя оставила) и не учитывает распроданное; `all` не уходит в фильтр; маппинг строки в карточку, включая отбрасывание тона плашки не из дизайн-системы и размеров вне сетки.
- `catalog.test.ts` (фронт) — сборка query-строки и обработка ошибок на подставном `fetch`: `all` и пустой поиск не отправляются, нулевой `offset` опускается, а нулевой `limit` — нет, не-2xx превращается в ошибку с путём и кодом.
- `plural.test.ts` — русское склонение, включая 11–14, которые по последней цифре просились бы в другую форму.

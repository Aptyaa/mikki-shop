# 018 — Примерочная «Наряди Микки»

Статус: **план** — код не написан. Документ описывает, что и почему строить.
Ступень G1 трека `docs/roadmap-game.md`.

Блокер: графика. Пока нет `mickey-base` и хотя бы десяти вещей слоями
(`docs/game-assets.md`), экран нечем наполнить.

## Что это

Экран, где Микки стоит посреди сцены, а вокруг — гардероб по слотам. Тап по
вещи надевает её, повторный тап снимает. Внизу две кнопки: «поделиться» и «взять
образ» — вторая кладёт в корзину те вещи образа, у которых есть товар в
каталоге.

**Игры здесь ещё нет.** Ни очков, ни события, ни победы, ни промокода — всё это
приходит в `019` и `021`. Ступень существует, чтобы построить сцену, гардероб и
модель данных, и уже на них проверить главное: интересно ли вообще одевать
Микки. Если нет — дальше идти незачем, и это выяснится за одну ступень, а не за
четыре.

## Экран

Маршрут `#/game`. В `Route` добавляется `{ name: "game" }`, разбор — тем же
способом, что остальные (`apps/telegram-app/src/lib/route.ts`).

Компоновка сверху вниз:

1. `ScreenBar` с заголовком «Примерочная» — **именно `ScreenBar`, а не `AppBar`**
   (правило из `001`: иначе на экране не будет маскота).
2. **Сцена.** Квадрат во всю ширину: фон из токенов, поверх — база Микки и
   надетые слои в порядке `feet → base → outer → neck → head`.
3. **Ряд слотов.** Пять кружков-вкладок; в активном слоте показан выбранный
   предмет. Слот с надетой вещью помечен, пустой — приглушён.
4. **Гардероб** активного слота — горизонтальная лента карточек.
5. **Действия.** «Взять образ» первичной кнопкой, «Поделиться» вторичной.

Нижнего бара на экране нет: примерочная — это полноэкранное занятие, и вкладки
под пальцем во время одевания только мешают. Выход — кнопкой «назад» в шапке.

**Вход в игру — карточка на главной** (`HomeScreen`), в ряду после новинок.
Пятая вкладка в баре не заводится: в `AppTabs.tsx` записано, почему их четыре.

## Данные

### Prisma

Две новые таблицы, префикс `Game*`. Существующие модели не меняются.

```prisma
/// Слот, куда надевается вещь. Пять, а не «одежда/аксессуар»: свитер под
/// курткой — нормальный образ, и на нём же считается «тепло» в 019.
enum GameSlot { FEET BASE OUTER NECK HEAD }

/// Вещь гардероба. Своя сущность, а не ссылка на товар: игре нужны вещи,
/// которых в магазине нет (колпак, панама), а каталогу — товары, которые никто
/// не рисовал. Связь необязательная и однонаправленная.
model GameItem {
  id        String   @id @default(uuid())
  slug      String   @unique
  title     String
  slot      GameSlot
  /// Путь к слою. Холст 1024×1024, прозрачный, см. docs/game-assets.md.
  image     String
  /// Порядок в ленте гардероба.
  sortOrder Int      @default(0)

  /// Товар, если вещь настоящая. Пусто — вещь только для игры: надевается,
  /// но в корзину не кладётся.
  productId String?
  product   Product? @relation(fields: [productId], references: [id], onDelete: SetNull)

  /// Свойства для оценки образа (019). Заполняются сразу: дозаполнять
  /// гардероб задним числом дороже, чем внести два поля при заведении вещи.
  warmth     Int     @default(0)   // 0–3
  waterproof Boolean @default(false)
  /// Доминирующий цвет ткани для проверки сочетания. Того же вида, что
  /// ProductColor.hex.
  hex        String?

  @@index([slot])
  @@index([productId])
}
```

`onDelete: SetNull` — намеренно: удалённый товар не должен уносить вещь из
гардероба. Образ, собранный вчера, не обязан разваливаться оттого, что позицию
сняли с продажи.

Сохранённые образы (`GameOutfit`) в этой ступени **не заводятся**. Выбранное
живёт в `localStorage` на клиенте. Таблица появится в `021`, когда образ станет
ответом в раунде и его придётся хранить на сервере.

### API

- `GET /game/wardrobe` — база Микки и весь гардероб, сгруппированный по слотам.
  У вещей с товаром — слаг, цена и доступные размеры, чтобы «взять образ»
  работал без второго запроса. Публичный (`@Public()`): играть можно и до входа.

Отдельного `POST` на «одеть» нет: сервер о примерке ничего не знает, пока она не
превращается в корзину. Гонять запрос на каждый тап — это лаг там, где его быть
не должно.

## «Взять образ»

Идёт через существующий `useCart().add()` теми же полями, что карточка товара.
Второй корзины не заводится.

Три вещи, которые нужно решить честно, иначе кнопка врёт:

1. **Размер.** Берётся из профиля питомца (`Pet.size`), если он заполнен. Если
   нет — открывается тот же `SizeSelector`, что на карточке товара, один раз на
   весь образ. Молча подставлять «M» нельзя: покупатель получит не тот размер и
   вернётся с претензией к магазину, а не к игре.
2. **Нет в наличии.** Вещь всё равно надевается — гардероб не перетасовывается
   при каждой продаже. Но в корзину не попадает, и рядом с кнопкой сказано,
   сколько позиций из образа доступно: «в корзину — 2 из 3, дождевик разобрали».
3. **Вещи без товара** (колпак) в подсчёте не участвуют вовсе и в тексте не
   упоминаются: покупатель не должен решать, что магазин что-то от него скрыл.

Цену считает бэкенд в `POST /cart/preview`, как и сейчас. Никаких «итого» из
данных гардероба.

## «Поделиться»

Картинка сцены, собранная на клиенте в `<canvas>`, и текст со ссылкой на Mini
App. В Telegram уходит через `shareURL` адаптера
(`apps/telegram-app/src/lib/telegram.ts`) — адаптер под это придётся дополнить,
это ровно тот случай, ради которого он и заведён отдельным файлом.

## Что здесь легко сделать неправильно

- **Сцена на `<img>` в потоке.** Слои обязаны лежать друг на друге в одном
  квадрате абсолютным позиционированием, иначе они разъедутся на первом же
  экране нестандартной ширины.
- **`max-width:100%` из `base.css` кита.** Именно это правило уже ломало маскота
  в `013` — сжало картинку до ширины родителя. У слоёв сцены ширину задаёт
  контейнер, и правило нужно перебить явно.
- **Вес.** Двенадцать слоёв по 768 px — это мегабайты. Грузить их вместе с
  каталогом нельзя: экран уходит в отдельный ленивый чанк, картинки — по мере
  открытия слота.
- **Тема.** Белый Микки на светлом фоне — та же ошибка, что в `013`. Фон сцены
  задаётся токеном и в тёмной теме темнеет вместе с приложением.

## Готово, когда

- Микки одевается и раздевается, слои сходятся, порядок правильный.
- Образ кладётся в корзину, размер берётся из питомца или спрашивается один раз.
- Распроданная позиция объяснена, а не молча пропущена.
- Проверено **в настоящем клиенте Telegram**, а не только в браузере: по
  `013` и `015` этот проект уже дважды ловил на разнице между ними.
- `pnpm run lint`, `typecheck`, `test`, `build` — чисто на чистом состоянии.

## Не входит

Оценка образа и событие дня — `019`. Промокоды — `020`. Спрятанный образ,
попытки и серия — `021`. Сохранение образов на сервере — вместе с `021`.

# Mikki Shop — правила работы

## В начале сессии
1. Прежде чем предлагать архитектурные решения или писать код — прочитай `ARCHITECTURE.md` и `ROADMAP.md`. Если задача касается конкретной фичи — проверь, нет ли уже файла `docs/features/*.md` под неё, и продолжай оттуда, а не с нуля.
2. **Создай ветку под задачу до первого коммита.** Не работай в `main` — он защищён и всегда должен быть зелёным и деплоимым.

## Ветки и коммиты

Trunk-based development: `main` — единственная долгоживущая ветка, всё остальное живёт 1–2 дня и вливается через PR.

- Именование: `feature/NNN-short-name` — тот же `NNN`, что у файла в `docs/features/`. Для остального — `fix/short-name`, `chore/short-name`.
- Ветка = один логический кусок работы. Если задача разрослась — режь на несколько PR, а не копи неделю в одной ветке: длинные ветки дают болезненные конфликты, особенно когда сессий несколько.
- Мержим через PR даже в одиночку — это то, что заставляет CI отработать до попадания в `main`. Squash merge, чтобы история `main` оставалась линейной и читаемой.
- Коммить по ходу работы, не копи всё в один финальный коммит.

## По окончании задачи/фичи
1. Обнови статус в соответствующем `docs/features/NNN-name.md` (создай, если фичи ещё нет: см. `docs/features/001-catalog-screen.md` как образец структуры).
2. Если фича закрывает фазу — отметь это в `ROADMAP.md`.
3. Убедись, что локально проходят `pnpm run lint`, `pnpm run typecheck`, `pnpm run build` — это ровно то, что гоняет CI.
4. Закоммить, запушить ветку и открыть PR (`gh pr create`). Не жди отдельной просьбы пользователя «зафиксировать».

## Параллельные сессии
Отдельных веток мало, если несколько сессий работают в одной и той же папке — они будут драться за один рабочий каталог. Под параллельную работу используй git worktree: своя папка на каждую ветку (`git worktree add ../mikki-shop-<branch> -b feature/...`), тогда сессии физически не пересекаются.

## Почему это важно
Несколько сессий могут работать над проектом параллельно и не видят live-переписку друг друга — только файлы в репозитории. Всё, что не закоммичено и не отражено в `docs/features/`/`ROADMAP.md`, для других сессий не существует.

## Стек (детали — в ARCHITECTURE.md)
TS-монорепо на pnpm workspaces, NestJS+Prisma+Postgres/PostGIS+Redis, React+Vite+Tailwind, российское облако (152-ФЗ). Не предлагать альтернативный стек без явного запроса пользователя.
